# Satya Python AI GM, AI Player & Hybrid RAG Skill (`satya-python-ai`)

## 1. Thin Python Orchestration Over Hybrid `satya_py` Package (`src/satya_py/`)
- Keep deterministic TTRPG math, 9-axis Psyche (`EGO`, `SLF`, `OPN`, `BLG`, `EXT`, `CNF`, `AGG`, `TRS`, `CPS`), social combat, spatial LoS/cover, Ch. 7/11/18/20–24 technical gear/EW/hazards, and *Awakened* substrate/arc/Part V mechanics in Rust exposed via `satya_py._native` (`crates/satya-py`, stubbed in `src/satya_py/_native.pyi`) and its typed domain submodules (`satya_py.{dice,combat,rules,maps,campaign,psyche,awakened,tech,schema}`).
- **Canonical Python Enums & Contract Tests (`src/satya_py/enums.py`)**: Use `StrEnum` classes from `satya_py.enums` (`CombatStance`, `MessageVisibility`, `ChannelContext`, `GmMemoryCategory`, `AiGmOperatingMode`, `AiGmTurnStatus`, `LogLevel`, `McpServerTier`, `CarryMode`, `BotchRule`, `SchemaDtoName`, `WireEnumName`, `normalize_combat_stance`) instead of bare `"stringly"` literals when building schema DTOs. `enums.py` synthesizes all Rust wire `StrEnum`s dynamically at import time from `satya_py._native` (`list_wire_enum_names()` / `list_wire_enum_codes(...)`), while `src/satya_py/enums.pyi` provides static `pyrefly`/IDE completion — never hand-copy Rust enum members into Python. Keep `RUST_ENUM_PARITY_MAP` verified via `tests/test_schema_contracts.py` (`test_python_strenums_match_rust_wire_enum_registry`). Note: `social_and_clocks.py` uses `WorldClock` slug `"daise"` (matching `crates/satya-campaign/src/world_clocks.rs`), NOT `AwakenedFactionId.GOVERNMENT_DAISE.lower()` (`"government_daise"`).
- Do **not** write parallel pure-Python mechanics or stdlib HTTP (`urllib`) fallbacks when adding or refactoring features; `pixi run test-py` depends on `build-py` (`src/satya_py/_native.pyd`) and `httpx` is guaranteed by `pixi.toml`, so both `satya_py` and `httpx` are always available in tests and runtime.
- **Prevent Rust↔Python Drift & Zero-JSON FFI**: PyO3 `0.27+` emits runtime `__text_signature__` (`inspect.signature(satya_py._native.<fn>)`). Keep FFI zero-JSON via `crates/satya-py/src/py_bridge.rs` (`PySerde<T>`, `PyEnum<T>`, `CodedEnum` from `satya-schema`) and `#[serde(default)]`/`#[serde(flatten)]` on canonical engine structs rather than `json.dumps`/`json.loads` shims or single-use `*Input`/`*Dict` FFI mirrors; whenever adding/changing a PyO3 binding or wire enum, run `pixi run gen-stubs` (`src/satya_py/_stubgen.py`) and verify with `pixi run check-stubs`, `test_satya_py_stub_matches_compiled_extension_exports`, and `pixi run pyrefly check src/satya_py`.
- **Guard Nullable FFI Returns**: Any PyO3 function returning `Option<PyJsonDict>` (e.g., `inspect_tactical_map_point`) returns `dict | None` in Python — always narrow (`pt = info if isinstance(info, dict) else {}`) before calling `.get(...)`.
- **Shared `satya_ml` Infrastructure (Abstract-to-Concrete)**:
  - **Session Stores & Reset (`src/satya_ml/session_store.py`)**: Reuse thread-safe, reentrancy-safe `SessionResetRegistry`, `SessionStore[T]`, and `CompositeSessionStore[K, T]` backed by the shared `_LockedStore[K, T]` (`GM_SESSION_REGISTRY` re-exported via `ai_gm/tool_spec.py`; `PLAYER_SESSION_REGISTRY` used by `ai_player/{tools.py,motivation_ledger.py}`).
  - **Signaling HTTP Client (`src/satya_ml/signaling_client.py`)**: Reuse `signaling_base_url`, `gm_service_token`, `service_auth_headers`, `load_ai_gm_toml_config`, and `http_get_json` / `http_post_json` / `http_post_json_detailed` (using `httpx` directly; never add `urllib` or `httpx = None` fallbacks). **Monkeypatch Contract**: tests patch module-local `_signaling_base_url`, `_http_get_json`, `_http_post_json`, `_http_post_json_detailed`, and `httpx.Client` on `ai_gm/{tools,maps,graph}.py` and `ai_player/tools.py` — keep thin module-local wrappers calling `signaling_client` and pass `client_cls=httpx.Client` (guarding `resp is None` from test fakes).
  - **FastAPI Server Base (`src/satya_ml/agent_server.py`)**: Subclass `BaseTurnEventPayload` and share `SessionLockPool`, `verify_service_auth`, and `resolve_turn_llm_config` across `ai_gm/server.py` and `ai_player/server.py`.
  - **Telemetry & Trajectory Builders (`src/satya_ml/ai_gm/telemetry.py`)**: Reuse `build_tool_invocation_record` and `build_trajectory_report_payload` across `ai_gm/{graph,party_coordinator}.py` and `ai_player/graph.py`. **Acyclic Boundary**: `telemetry.py` must **never** import `signaling_client.py` (which imports `current_trace_headers` / `record_emitted_event_id` from `telemetry.py`).
  - **CSPRNG & Map/Psyche/Substrate Delegation**: Reuse `satya_py.dice.{roll_d20_pair,roll_d20_pairs}` in `ai_gm/rolls.py` (`ContestedRollRequest.to_rust_pairs_dict()`), `satya_py.awakened.evaluate_substrate_condition_impact` in `party_coordinator.py`, and `satya_py.maps.sanitize_tactical_map_for_player` in `motivation_ledger.py` (always follow with `clean.pop("notes", None)` and strip `"spatial_pins"` from `narrative_manifest` for player isolation). Normalize `CombatantTickEntry.active_stance` safely with a `try/except ValueError` fallback around `normalize_combat_stance` because narrative technique strings (`"SNAP_SHOT (T4/C4/F3, MORALE=STEADY)"`) are valid `Option<String>` entries on the Rust wire.
- **Zero Duplicated Tool Shims or Opaque `params_json` Blobs**: Never copy-paste `_FallbackToolWrapper` into domain modules (import `satya_gm_tool`, `tool`, `register_session_reset_hook`, `SessionStore`, and `CompositeSessionStore` from `src/satya_ml/ai_gm/tool_spec.py`). Prefer Pydantic v2 discriminated-union `args_schema` models (`Field(discriminator="mode")`) backed by `ABC` execution bases (`ToolRequest(BaseModel, ABC)` / `ContextToolRequest[Ctx](BaseModel, ABC)` with `@abstractmethod def execute(...)`) and structural `Protocol`s (`Executable[R]`, `ContextualExecutable[Ctx, R]`) over untyped `params_json: str` strings and `if/elif` dispatchers.
- **Python 3.14 Typing, Generics & Functional Style**: Use PEP 695 `type` aliases and generic syntax (`class Store[T]`, `def dispatch[Req: Executable[...]]`), `Literal[...]` for closed domain sets, `Final` + `MappingProxyType` / `frozenset` / `tuple` for constant lookup tables (never bare mutable module or per-call `dict`/`set` literals), `TypedDict` (with `NotRequired`) for structured dict contracts, and `@dataclass(frozen=True, slots=True)` records instead of anonymous tuples. Prefer functional composition (`next(...)` with generators, `sum(...)`, pure predicate methods, `functools`) over nested imperative `for`/`break` accumulator loops.
- Organize `.py` files by cohesive domain responsibility (`social_and_clocks.py`, `npc_psyche_combat.py`, `audit_and_first_contact.py`, `awakened_systems.py`, `tech_and_tradecraft.py`, `rag/{corpus_builder,hybrid_index}.py`) rather than accumulating unrelated tools in `tools.py`, `graph.py`, or `maps.py` — split by concern, not line count.

## 2. Single-Source Checklist When Adding or Renaming an AI GM `@satya_gm_tool`
Every new LangGraph AI GM tool is driven from one `@satya_gm_tool(...)` registration in `src/satya_ml/ai_gm/tool_spec.py`:
1. **Decorate with `@satya_gm_tool`**: Implement in a focused domain module under `src/satya_ml/ai_gm/` using `@satya_gm_tool(pack=..., tier=..., ooc_readonly=..., session_scoped=..., args_schema=..., campaign_packs=...)`. This single decorator registers the tool for `get_builtin_gm_tools()`, `CORE_GM_TOOL_NAMES` / `DEFERRED_TOOL_PACKS` / `OOC_READONLY_TOOL_NAMES` (`tool_registry.py`), telemetry tier classification (`_classify_tool_tier` in `graph.py`), and `session_id` injection. If adding an entirely new deferred pack ID, also add its description/keywords to `_PACK_DESCRIPTORS` in `src/satya_ml/ai_gm/tool_registry.py`.
2. **Session Reset Hook**: If the module holds any `_SESSION_*` state, register its per-module cleanup function with `@register_session_reset_hook` (so `reset_session_npcs` / `reset_social_and_world_state` invoke it cleanly via `run_session_reset_hooks` with zero chained cross-module imports).
3. **Package Re-Export**: Export the tool (and any public session reset helpers) in `src/satya_ml/ai_gm/__init__.py`.
   - *Campaign Pack & Preset Precedence*: `config/campaign.toml` is embedded once in `satya-campaign` (`crates/satya-campaign/src/campaign_packs.rs`) and consumed by both `satya-signaling` and `src/satya_ml/campaign_config.py` (via `satya_py.campaign.get_embedded_campaign_config()`); never add duplicated pack fallback tables in Python or Rust. In `infer_sector_preset` (`src/satya_ml/ai_gm/maps.py`), update `_SECTOR_PRESET_RULES` preserving specific phrases before generic keywords — never match bare setting proper nouns ahead of venue nouns.

## 3. Session Seeding Order & Cyclic-Import Pitfalls
- **Lazy Import Verification**: `graph.py` ↔ `tools.py` ↔ `scenario_director.py` ↔ `party_coordinator.py` have runtime import cycles. Whenever adding a helper call (e.g. `get_active_campaign_pack_name()`) inside one of those modules, verify the symbol is imported in scope by running `pixi run pyrefly check <edited_files>` before launching full pytest.
- **`world_ledger` Economic Tier Seeding Order**: Tools calling `get_session_world_ledger(session_id)` lazily seed a default `MIDDLE_CLASS` ledger if none exists. In tests or scenarios requiring `LOW_INCOME` / `DESTITUTE` / `WEALTHY` baseline strain, call `generate_tactical_map(..., economic_tier=...)` (or seed the world ledger explicitly) **before** calling telemetry/social/grid tools.
- **Fast Python / Lore-Only Pytest (Skip `build-py`)**: `pixi run test-py` forces `depends-on = ["build-py"]` (`--release` Rust compile). Whenever `.rs` files and `docs/ttrpg/*.md` were not modified, run targeted or parallel pytest directly with `PYTHONPATH=src` instead: `pixi run python -m pytest tests/<relevant_test>.py` (or `pixi run python -m pytest -n auto --dist loadfile tests`), avoiding release Rust rebuilds and `src/satya_py/_native.pyd` Windows file locks.
- **Offline Signaling in Tests**: `tests/conftest.py` short-circuits offline signaling HTTP retries so `pixi run test-py` (`pytest -n auto --dist loadfile tests`) finishes in ~11s across workers. Keep per-test `session_id` strings unique within a test file.
- **Windows Locked `src/satya_py/_native.pyd` Fallback (`os error 32`)**: If a live server (e.g., `satya_ml.ai_gm.server`) holds `src/satya_py/_native.pyd` open on Windows, `pixi run build-py` / `pixi run test-py` will fail updating `src/satya_py/_native.pyd`. Never kill the user's running server; instead compile with `cargo build --offline --release -p satya-py`, restart or isolate the lock before replacing `src/satya_py/_native.pyd` in place. Also scope quick `pixi run pyrefly check <edited_files>` runs to touched files first so pre-existing unrelated repo errors don't mask regressions.

## 4. Hybrid PyLance RAG & Player/GM Visibility Wall (`src/satya_ml/rag/`)
- Corpus lives at `data/lance/satya-knowledge-rag.lance` (`pixi run build-rag`), indexing `ttrpg_rules` (H1/H2/H3 + 12-row header-preserving table slices), `rust_engine` symbol cards, and `campaign_lore` (`PUBLIC`, `ARC2_SATYANG`, `GM_CONSPIRACY_SECRET`).
- **Strict Visibility Invariant**: Any AI Player tool (`src/satya_ml/ai_player/motivation_ledger.py` `lookup_public_lore_and_npcs`) **must** query `SatyaHybridRagIndex.search(..., caller_role="player")`, which enforces `visibility == "PUBLIC"` so `GM_CONSPIRACY_SECRET` / `ARC2_SATYANG` chapters (`04-chronicle-and-gm/`, `01-opening/prologue.md`, `03-minds-and-factions/satyang_and_four_pillars.md`) never leak to player agents.
