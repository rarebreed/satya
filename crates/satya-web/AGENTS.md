2. **Mandatory Browser & SSR Contracts**:
   - **One-Shot SSR + `bind_window_callbacks!`**: `SatyaApp` is not client-hydrated. Every `window.satya*` handler emitted by SSR or `format_*_html` formatters must be registered in `bind_window_callbacks!` (`wasm_client/mod.rs`), including multi-floor switcher callbacks (`satyaSelectMapFloor`, `satyaMoveTokenToFloor` backing `#map-floor-switcher`), and every SSR `id="..."` attribute must be globally unique (`tests.rs`).
   - **Shared Helpers & Core Crates**: Reuse `dom.rs`, `dom_tooltip.rs` (`TooltipClampSpec`, `StickyHoldToggle`, `sync_floating_tooltip_dom`, `is_keyboard_typing_target`), `wgpu_shared.rs`, and `map_3d_diorama_mesh.rs`; import `SECONDS_PER_TICK` (`0.25`), tactical map/hover math, and catalogs directly from `satya-engine` and `satya-schema`.
   - **Host Verification**: Keep HTML formatters, tooltip math, CPU 3D mesh builders, and `naga` WGSL shader checks host-testable (`cargo test --offline -p satya-web`).
   - **Wasm Verification (mandatory)**: Host builds skip `#[cfg(target_arch = "wasm32")]` code, so also run `cargo clippy --offline -p satya-web --target wasm32-unknown-unknown -- -D warnings` (and `cargo build --offline --release -p satya-web --target wasm32-unknown-unknown` when touching `Cargo.toml`, Wasm bindings, or large 3D/map modules, with `.pixi\envs\default\Library\bin` on `PATH`). Keep `wasm-opt = false` (`Cargo.toml`) and `--no-opt` (`pixi.toml` `build-wasm`) intact on Rust `1.99+`, and enable any new `web-sys` type features in the root `Cargo.toml`. See [`satya-rust-web`](../../.agents/skills/satya-rust-web/SKILL.md) section 6.
