# `satya-py` Agent Coding & Architecture Rules

Activate [`satya-rust-workspace`](../../.agents/skills/satya-rust-workspace/SKILL.md), [`satya-rust-engine`](../../.agents/skills/satya-rust-engine/SKILL.md), and [`satya-python-ai`](../../.agents/skills/satya-python-ai/SKILL.md) when modifying `crates/satya-py` or Python consumers in `src/satya_ml/` and `notebooks/`.

1. **Thin Hybrid PyO3 (`abi3-py312`) Package (`src/satya_py/`) — Zero Duplicate Math or Spatial Geometry**:
   - **Native + Domain Submodule Architecture** (`src/satya_py/__init__.py` re-exports all compiled `_native` bindings plus 10 typed domain submodules):
     - `crates/satya-py/src/lib.rs` (`#[pymodule(name = "_native")]`): Module root plus `2d20` Cascade/Triad evaluation, `.to_dict(py)` projections on `PyCascadeRollOutcome` / `PyTacticalPoolEnvelope`, `evaluate_tactical_triad_from_dict`, Rules Book lookup, and GDPR helpers.
     - `crates/satya-py/src/schema_py.rs`: `SchemaRegistry` (`CRC-64-AVRO` framing, Avro `.avsc` field extraction, GDPR manifest), `SCHEMA_DTO_NAMES` + `validate_schema_dto`, canonical `satya-schema` DTO normalization (`normalize_character_sheet_record`, `normalize_tactical_map`, `schema_default_record`), and macro-generated `wire_enum_registry!` (`list_wire_enum_codes`, `list_wire_enum_names`).
     - `crates/satya-py/src/tactical_map_py.rs`: Spatial collision/destination resolution, LoS/cover evaluation, sector generation/continuation, floor switches, passive perception, `infer_token_model_preset`, and `sanitize_tactical_map_for_player`.
     - `crates/satya-py/src/hooks_and_npc_py.rs`: Party motivational hook compilation, lifepath anchors, and pack-aware NPC profile generation.
     - `crates/satya-py/src/psyche_social_py.rs`: 9-axis Psyche empathy/dissonance/conviction/drift, `list_psyche_trait_descriptors`, social combat, morale triggers, and `SessionWorldLedger` wrappers.
     - `crates/satya-py/src/awakened_systems_py.rs`: Split-brain synthetic substrate state (`evaluate_substrate_condition_impact`, `default_polycrisis_district_state`), L0/L1 cage/hunter AI evaluation, conspiracy ledgers, polycrisis grids, tradecraft, dissenter/proxy hooks, and Part V affective clamping & 4-bloc political economy.
     - `crates/satya-py/src/tech_and_gear_py.rs`: Ch. 7 stealth/tail/forensics, Ch. 11 contacts/cover/safehouses, Ch. 18 blast/breach, Ch. 20 vehicle chases/trauma, Ch. 21 hazards, Ch. 22 custom gear design, Ch. 23 drones/chassis/co-design/cybernetics, and Ch. 24 EW intrusion/ECM/ECCM/hardware.
     - `src/satya_py/{enums,dice,combat,rules,maps,campaign,psyche,awakened,tech,schema}.py`: Pythonic typed submodules (`enums.py` provides `StrEnum` mirrors, `SchemaDtoName`, `WireEnumName`, `normalize_combat_stance`, and `RUST_ENUM_PARITY_MAP` verified against Rust via `tests/test_schema_contracts.py`) delegating directly to `satya_py._native` (stubbed in `src/satya_py/_native.pyi`, marker `src/satya_py/py.typed`), synchronized by `src/satya_py/_loader.py`.
   - Always delegate dice/cascade math, tactical map collision/LoS/hover geometry, passive perception checks, motivational hook compilation, social combat/Psyche mechanics, Awakened substrate/conspiracy/polycrisis/tradecraft mechanics, Ch. 7/11/18/20–24 rules, world clocks, and Avro `CRC-64-AVRO` checks to `satya-engine` and `satya-schema`. Normalize flexible Python inputs via `merge_object_defaults<T>` (seeded from `T::default()` + Serde `#[serde(default)]` on canonical structs) in `tactical_map_py.rs`, `hooks_and_npc_py.rs`, `psyche_social_py.rs`, `awakened_systems_py.rs`, and `tech_and_gear_py.rs` rather than creating duplicate `*Input` / `Py*Params` mirror structs; evolve schemas in `satya-schema` cleanly when downstream ergonomics require it (keeping `v1` wire compatibility tests green).
   - **Zero-JSON FFI, Shared `py_bridge` & Anti-Drift Discipline**:
     - Centralize shared FFI utilities (`PySerde<T>`, `PyEnum<T>`, `PySerdeEnum<T>`, `unwrap_py_enum_or`, `unwrap_py_serde_enum_or`, `merge_object_defaults<T>`, `PyJsonDict`, `PyJsonList`, `PyJsonInput`, `PyListInput`, `to_py_err`, `to_py_object`) in `crates/satya-py/src/py_bridge.rs`. Note: `to_py_object` (`pythonize`) stringifies integer JSON map keys — build explicit `PyDict` entries for `dict[int, float]` PMFs (`compute_contested_cascade_odds`, `compute_lifepath_skill_progression`).
     - Use `PyEnum<T>` / `PySerdeEnum<T>` for required strict enums and `Option<PyEnum<T>>` + `#[pyo3(signature = (..., param=None))]` + `unwrap_py_enum_or(...)` for defaulted enum args (preserving Python kwarg names), keeping lenient filter/theme hints (`from_code_str`, `SectorPreset::infer_from_theme`) as `Option<&str>`/`&str`.
     - Expose FFI enums via `define_coded_enum!` / `CodedEnum` (`satya-schema` / `satya-engine`) and model multi-mode Python requests with Serde internally tagged enums (`#[serde(tag = "action", ...)]` / `#[serde(tag = "kind", ...)]`) rather than manual `serde_json::Value::get` chains or repetitive `impl Default` mirror structs.
     - Keep `#[pyo3(signature = ...)]` parameter names, ordering, and defaults strictly synchronized with `src/satya_py/_native.pyi` (auto-generated via `pixi run gen-stubs` / `src/satya_py/_stubgen.py`).
     - For pure-Python helpers in `src/satya_py/*.py`, follow the workspace Python 3.14 standard: PEP 695 `type` aliases & generics, `Final` + `MappingProxyType`/`frozenset`/`tuple` module constants (no bare mutable dicts/tuples rebuilt per call), `TypedDict` structured returns, covariant `Mapping`/`Sequence` parameters, `ABC`/`Protocol` contracts where polymorphic, and functional expressions (`next(...)`, `sum(...)`) over imperative loops.
2. **Pixi Build, Clippy/Test & Auto-Generated `src/satya_py/_native.pyi` Stub Sync**:
   - Always run commands via `pixi run ...` (never call `.pixi/envs/default/*.exe` directly or hardcode external `uv` Python paths).
   - Run `pixi run cargo clippy --offline --no-default-features -p satya-py --all-targets -- -D warnings` and `pixi run cargo test --offline --no-default-features -p satya-py` (`--no-default-features` disables `auto-initialize` so Rust test binaries link cleanly), and run `pixi run build-py` to compile release `satya_py` and update the gitignored `src/satya_py/_native.pyd` binary.
   - `src/satya_py/_native.pyi` is auto-generated from Rust sources + runtime `inspect.signature` (`src/satya_py/_stubgen.py`): regenerate with `pixi run gen-stubs` whenever `#[pyclass]` or `#[pyfunction]` exports change, and verify with `pixi run check-stubs`, `test_satya_py_stub_matches_compiled_extension_exports`, and `pixi run pyrefly check src/satya_py`.
3. **AI GM Consumers**: Follow [`src/satya_ml/ai_gm/AGENTS.md`](../../src/satya_ml/ai_gm/AGENTS.md) and [`docs/technical/ai-gm-agent-design.md`](../../docs/technical/ai-gm-agent-design.md).
